# గాయత్రి వన్ పరిచయ పేజీ, పంచుకునే సదుపాయం

## ఇప్పటికే ఉన్నవి
- వ్యక్తిగత వివరాల పేజీ, ఉద్యోగ ప్రకటన తయారీ, తయారైన ప్రకటన వీక్షణ.
- ఫోన్ ప్రధాన తెరపై జోడించే బటన్.
- పరిచయ సంఖ్యతో సాధారణ పంచుకునే సదుపాయం.

## కొత్తగా చేయాల్సినవి
1. ప్రతి వ్యక్తి తన సేవల పరిచయ పేజీ సిద్ధం చేసుకోవడం: పేరు, సేవలు, పరిచయం, తన ఫోటో, చేసిన పనుల ఫోటోలు.
2. ఇతరులకు చూపించడానికి స్పష్టమైన అనుమతి. అనుమతి ఇవ్వని వివరాలు, ఫోన్ నంబర్, రహస్య ఖాతా వివరాలు బయటకు రావు.
3. పరిచయ పేజీలో పంచుకునే బటన్: “నా పరిచయం, నేను చేసిన సేవలు, అభిప్రాయాలు చూడండి” అనే సందేశంతో వ్యక్తి పేజీ చిరునామా పంపడం.
4. నమోదైనవారు నిజమైన అభిప్రాయాలు, నక్షత్రాల అంచనా ఇవ్వడం; తన సేవకు తానే అభిప్రాయం ఇవ్వకుండా అడ్డుకోవడం. సేవ తీసుకున్నట్లు ఆధారం లేకుండా ధృవీకరించిన అభిప్రాయం అని చూపించకూడదు.
5. మెచ్చుకోలు, వీక్షణల లెక్క. ఒకరి మెచ్చుకోలు ఒకటే; వీక్షించినవారి రహస్య వివరాలు బయటకు చూపించకూడదు.
6. పని ఫోటోలు జోడించడం, తొలగించడం; ఇతరుల ఫోటోలు పెట్టడానికి అనుమతి కోరడం.
7. ఫోన్‌లో వివరాలు సేవ్ చేసి, పేజీ తెరిచి, పంచుకుని, అభిప్రాయం/మెచ్చుకోలు కనిపిస్తున్నాయో పరీక్షించడం.

## పంచుకునే చిత్రం
కొత్త చిత్రం సిద్ధమైంది. ఒక నెల పూర్తి సభ్యత్వం: ₹99 చెల్లించి వ్యక్తిగత స్థితిలో పెట్టి తొమ్మిది మందికి లేదా తొమ్మిది బృందాలకు పంపాలి; పంచుకోకపోతే ₹499. పరిచయ సంఖ్య ఇవ్వలేదు కాబట్టి ఖాళీ స్థానం ఉంది. చిత్రం సిద్ధం కావడం వల్ల చెల్లింపు నిబంధనలు యాప్‌లో అమలైనట్లు కాదు.

## ఇంకా స్పష్టత కావాల్సిన పాత పనులు
- 5, 10, 15, 20 మంది బృందాల ధరలు ఇవ్వలేదు.
- పరిచయ ఆఫర్ ముగింపు తేదీ నిర్ధారణ లేదు; అసలు గడువు సభ్యులకు చూపాలి.
- బయట పంచుకున్న ఆధారం ఎలా ఆమోదించాలి అనేది నిర్ణయించాలి; స్వయంగా నిర్ధారించినట్లు చూపించకూడదు.
- నిజమైన ఫోన్ ధృవీకరణ, యాప్ మూసినప్పుడు సమాచారం రావడానికి అదనపు సేవ ఏర్పాట్లు అవసరం.

## Technical implementation
- Keep private `profiles` separate from an opt-in public service-profile record; never grant anonymous access to private account rows.
- Add focused review, like, photo and deduplicated view storage with explicit grants, RLS, ownership validation and authenticated writes.
- Use a public profile route with unique metadata and an authenticated owner editor. Keep existing synthetic sign-in credentials unchanged.
- Use the Storage API for uploads with ownership policies; use narrowly projected public reads and server-side authorization where needed.
- Add concrete privacy, ownership, self-review and like-deduplication tests, then verify the real signed-in flow at phone widths.
